# QQ 音乐歌词更新与封面引用（2026-11-17）

## 问题及最小修复

用户反馈：QQ 音乐用不断变化的媒体标题显示歌词时，仪表文字似乎闪烁。这是用户观察，尚无精确到每次闪烁的元数据/车机显示对照日志。

源码确认的触发链：`MediaListenerService` 在没有 `MEDIA_ID` 时把标题纳入封面归属键；每句歌词都会变成新归属，`ArtworkRepository` 清除当前图片，`Iap2ArtworkSender` 在加载期间撤去引用，图片完成后恢复。内容摘要去重发生在加载之后，不能避免中间的撤引用。

本次仅将封面身份从显示标题中分离：会话、播放器及可用的 `MEDIA_ID` 优先；缺少 ID 时沿用原有歌手、专辑、时长判据，移除标题。键值比较提取为纯函数，原有 `artworkIncarnation` 仍负责归属代次。元数据回调继续递增 revision，同归属加载时保留现有图片，加载完成后沿用已有内容去重。

没有增加重试、延迟、超时或兜底，没有改连接时序、音频、默认配置与版本号。未整体移植上游 `f0124c9` 的发送窗口/封面超时策略。完整校验要求修正同文件回调注册表达式的 lint 缩进报错，改动仅为表达式排版。

## 两种模式与验证范围

- 普通音乐：歌词仍按媒体标题更新。回归测试在新 revision 图片读取被阻塞时检查原封面 ID 仍存在、歌词已经写入 `0x5001`；相同图片完成后没有新文件传输。
- 真正封面变化：同归属的新图片仍能更新 ID；明确无封面的结果仍能撤去旧图。会话、播放器、媒体 ID，以及无 ID 时歌手/专辑/时长变化仍产生不同身份。
- 导航混合：导航标题及道路字段、导航封面保持；歌词通过音乐快照进入专辑栏。测试确认不加载音乐封面，切回普通音乐后能够加载并使用音乐图，不混用导航图。

边界：缺少媒体 ID 且歌手、专辑、时长完全相同的两首歌无法仅凭这些字段区分；不再通过标题猜测切歌，实际图片仍由已有 revision/内容更新机制处理。此时加载期间可能暂时保留前图。这是避免把歌词当作换歌的明确取舍，没有新增歌曲识别启发式。
