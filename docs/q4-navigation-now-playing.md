# Q4 仪表正在播放：音乐/导航选择

用户授权的首版实验，只更换发送给车机的NowPlaying来源，不建立假的Android MediaSession，不更改音频、地图或媒体按键。手机“车机显示”卡新增“仪表导航信息”开关，默认关闭（音乐），保存用户选择；不保存路线/目的地数据。此前研究文档单独提交，业务实现与测试单独提交。

## 数据与生命周期

沿现有7240控制读取/0x10030 HUD订阅接入完整字段6，正文仍不写日志。每个HU拥有独立source身份；旧HU的输入和结束不能处理新HU状态，最终CarLife stop立即清空。两种CarLife/CarPlay启动顺序都使用同一provider，音视频交接逻辑不变。音乐模式仍记录导航，导航模式仍由原监听器维护真实音乐快照。切换后所有蓝牙/WiFi NowPlaying provider经同一选择入口，恢复最新音乐；没有音乐时显式清空导航显示为“暂无音乐”。没有新增车辆速度上报或0x1003B探测。

纯状态机NavigationState负责无IO状态；NavigationNowPlaying负责偏好、每秒刷新请求和图片仓库。只在导航模式且存在HU时安排每秒刷新；关闭模式或HU结束取消刷新。HUD快速更新以250ms窗口合并，显示在后续provider读取或每秒刷新时收敛。图片完整解码与占位PNG生成仅在已有有界ArtworkRepository工作线程；有像素/尺寸上限。相同图片内容保持稳定source身份，不随距离更新重传。

默认active=false。首次action3/turn24/distance1记录目的地并置true；active=true时相同类型通知整条忽略，包括名称、图标，不刷新状态。引导1/2也可补建active状态，处理首次目的地通知缺失/中途切入。action3/24/0置false并进入5秒保留，重复0不延长；结束优先保留首次目的地图而非上个转向箭头。新目的地或引导取消旧结束期限，过期逻辑没有跨代异步任务。最终断开与HU更换立即清空，不等待5秒。

按用户“只有0才确信结束”的约束，模块idle单独不清理目的地，其他action3也不冒充到达；若手动取消导航只发模块idle而不发结束包，首版可能保留旧信息至新导航或断开，需要短测核验。不用短无包超时判结束，停车可能很久不更新。

转向按候选TURN_NAMES，并按用户实车确认补25=进入隧道；未知为导航指引，不猜箭头。小于1000直接米，大于等于1000为一位小数公里。action1/转向变化/近零后距离重置/明显距离跳升用于新片段判定，Road为交叉证据，单纯action2道路名称补全不重置进度。距离跳升阈值max(100米,片段起始距离20%)是首版启发式，不宣称已解决所有重规划或同名同向路段。短时字段分批更新合并后再判定。

## 百分比进度

总媒体时长固定100000ms，elapsed=clamp((起始距离-剩余距离)/起始距离,0,1)×100000ms；全状态STATUS_PAUSED，不按时间外推。66%在Q4可能显示1:06|-0:34，这不是ETA。初始距离0不计算进度。中途开始观察只能建立当时的基准。Q4暂停状态是否显示条、emoji字体及空歌手的默认文字均待实车，不能以编码单测推定显示成功。
