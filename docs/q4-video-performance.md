# Q4 视频直通性能优化

独立于音频优化提交。不改变 H.264 样本、码率、帧率、分辨率、画布契约或丢帧策略，不构建 APK。

- 普通帧 NAL 拆分使用原数组切片，避免逐 NAL 复制和额外起始码列表。
- AVCC 按 NAL 长度前缀直接写入工作区，移除每帧 ByteArrayOutputStream 与 toByteArray 复制。
- ChaCha 复用输入/输出数组，保留每帧 cipher 初始化和原计数器/重连语义；AES 保留跨帧连续密钥流，在最终输出负载区原地加密。
- 视频头和密文合并为同帧一次同步 write，仍在原 writeLock 中完成，不跨帧攒包。
- IDR 与 SPS/PPS 缓存仍拥有独立副本，避免上游输入修改或工作区重用破坏保活。源重启、等待 IDR、配置发送、保活及背压恢复逻辑保留。
- 每个常驻数组最多保留 8MiB 容量；更大合法帧使用临时数组，不因工作区上限拒绝帧，不长期钉住超大内存。

验证：447 项单元测试全部通过，失败/错误/跳过均为 0；lint 与 git diff --check 通过。新增测试覆盖旧 NAL 拆分/AVCC 等价、混合起始码、随机输入、ChaCha 增长/缩小和计数重置、AES 跨帧连续性、缓存独立所有权、超大帧以及实际 TCP 连续写入/保活穿插不消耗帧 nonce。

尚待：Android 实车的 CPU、分配率/GC、发送延迟、长期播放与重连验证。本提交未进行手机性能实测，不声称量化 CPU 或功耗收益。
