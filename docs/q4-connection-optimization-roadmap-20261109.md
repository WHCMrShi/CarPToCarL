## 顺序、范围与验证

### 1. MFi 认证失败分类（用户已授权，当前只实施本项）

确定缺陷：Iap2SenderSession.runMfiChallenge 在挑战期间读到断链时，将当前长度写入 recordHardRejected，甚至删除成功记忆。Q4 既有日志出现 20B 断链后，下一轮绕行 32/16B，最终又收到 20B 响应的反例。

修复目标（用户随后补充：Q4 多次实测只接受 20B，冷车初次认证可能失败）：

- 本 Q4 构建蓝牙及 Wi-Fi iAP2 固定 20B，取消 20/32/16B 探测与按记忆选长度；不继续做其他车型兼容判断。
- 冷启动超时或 0xAA04 可在同一链路有限重传一次同一份随机挑战；每次最多等待 6 秒，蓝牙仍受原会话总预算约束。复用挑战是同一逻辑请求的重传，迟到签名不归给另一份挑战。
- 传输中断、超时、拒绝均不否定已验证的 20B 适配结论，不改写既有成功/长度失败记忆；仅收到当前链路签名时记录 20B 响应成功。
- 真正断链结束本轮，交现有连接机制恢复；新链路生成新随机挑战。重试耗尽不假发 0xAA05，旧隧道/重复应答不得修改新会话记忆。
- 不增加密码学/配对协议，不清空历史记忆、不无限重试；不改首帧接管、网络身份及恢复预算。
- 测试涵盖旧记忆不影响固定长度、断链保留记忆、首次拒绝后恢复、静默后迟到签名、重试耗尽、总预算和重复/退役响应。

### 2. 直通关键帧请求闭环（待单独授权）

当前 forceKeyFrame 调用 VideoSender.requestKeyFrame，直通分支返回 true 而未请求源；本地日志误称已经编码。现有 attach/首帧恢复会请求编码器重建，不能称全系统没有 IDR 请求。

将请求转交当前 CarLife 源，区分请求转交、新同源 IDR 到达、配置/IDR 写成功。重建请求必须合并、限流并检查当前 owner/源代次，不阻塞事件线程。今早日志没有 forceKeyFrame，不将此缺口认定为两次失败根因。

### 3. 屏幕/音频资源仲裁（待单独授权）

当前所有 changeModes 均固定 assertModes 声明屏幕与音频。Q4 日志真实出现 PHONE/PHONE_END、RVC/RVC_END、POPUP 与 requestUI，各场景请求不同。

先核验 Q4 请求枚举、期望归属与响应；屏幕和音频分开，永久归属和 borrowID 临时借用分开，结束时恢复此前状态。保留晚到真实源一次性接管，增加当前用户意图/资源状态约束，避免来电/倒车期间被恢复任务重新抢占。未知请求不猜测 CPC USB 枚举。测试涵盖嵌套借用、重复结束、断线/新代次，资源让出不等于拆 Wi-Fi 会话。

### 4. 蓝牙到 Wi-Fi 交接空窗（先观测，确认后另立修复）

参考抓包在关联后结束蓝牙、随后启动 AirPlay；当前 Q4 代码在视频运行或 Wi-Fi 和 AirPlay 控制均有效时保留建链，尚需检查网络已就绪、RTSP 未连上时是否误取消。

只在当前目标身份/邀请、固定网络租约、工作代次成立且已有未完结建链工作时，评估有限继续机会。没有证据时不无条件放宽；用户取消、终态和过期仍立即有效，不无限延长 startup/departure 预算。

### 5. 已就绪路径的重复等待与重建（待稳定基线后评估）

按端到端关键路径计时，不能相加并行阶段。Q4 历史样本 AirPlay 配对约 0.5s、基础 SETUP 约 0.1s，优先减少认证绕行及已有网络证据下的重复等待，保留当前精确身份验证/入网门禁。

ctrl 广播已在启动时提前发布、网络绑定后重注册，不重复实现。评估新鲜缓存 GOP 正常起播后是否仍需立即重建编码器；以当前源、SPS、GOP 完整性与实时写出为门禁，失败才恢复。不得为等 CarLife 无限阻塞车机视频建链窗口。

### 6. 静态保活与参考链（独立实验）

静态低帧率、源失活、下游写阻塞分别判断。重播旧 IDR 可能回退可见画面；恢复 P 帧若依赖重播前参考状态，可能参考不一致。尚无本车复现证据，不能直接删除保活或任意丢 P 帧。

记录真实源最后帧龄、IDR 年龄、重播、队列/写时限与恢复首帧类型，分别测试静态主页、动态地图、停源和网络受限。继续保留 WriteDeadline、有界队列和数据口恢复。
