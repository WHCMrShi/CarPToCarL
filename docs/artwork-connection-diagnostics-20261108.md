## 新日志如何定位封面

搜索 `ARTWORK:`，按 BT/WiFi 链路分别看：

1. `peer-SYN`：真实会话表、最大长度、窗口、重传参数。
2. `subscription field=... gate=...`：是否订阅字段 26/20，是否支持当前文件协议。`no-unique-kind1-v2-session` 是实现未匹配，不能断言硬件不支持。
3. `metadata`：媒体会话是否存在；是否提供 ALBUM_ART、ART、URI。只有键是否存在，不强制在回调线程读取图片。
4. `skip`：尚未进入图片 IO；`prepare`：来源状态。状态未变不逐秒重复。
5. `load-queued/start`、`source`、`prepared-input`、`load-result/timeout`：图片读取与编码路径、输入输出大小、是否取消或允许发布。缓存可能省略实际编码，不把读取成功描述为重新压缩。
6. `selected`、`reference-queued`：图片 ID 和引用字段；ID 128 表示清空图片，不是实际封面。
7. `file-queued type=4`：SETUP 已入链路队列；`response status=1` 为 START，之后才发送数据。
8. `file-link-send/ack/RTO/EAK`：链路发送与可靠传输。只对 SETUP/尾包记录常规发送及 ACK，重传单独记录，不逐分片刷成功日志。
9. 尾包后 `response status=5` 为文件层 SUCCESS；2/6 为取消/失败，3 为暂停；超时会带阶段和已发送字节。若这些都完整但仪表无封面，下一步检查引用字段、文件内容/格式与车机呈现要求。

## 连接与独立日志保留

搜索 `CONNECT-DIAG:`、`STAGE:`，结合原有 BT、Wi-Fi、ctrl、mDNS、pair-setup/verify 日志。
`schema=20261108-v1` 标识本诊断包；每个 AirPlay 实例的 client 数字仅用于同一进程关联，不是设备身份。

主日志仍约 2MB 轮转；后台日志工作线程另保存三个文件：

- `main_debug.log.diagnostic-start`：本进程最早的关键诊断，最多 512,000 字节，满后不覆盖。
- `.diagnostic-previous` / `.diagnostic-recent`：最近两段关键诊断，各最多 512,000 字节。
- 启动下一个进程时重建诊断归档。不会无限保留历史进程，三段合计约 1.5MB。

导出会附上这三段和现存主日志，保留原时间戳，以标题区分重复区间与可能轮转的中段。不保证全程逐行连续；异步日志队列若过载仍可能丢记录，归档会标注已知丢弃数量。归档失败不阻止主日志写入，读取失败不丢弃可用主日志。

独立归档不收 RAW 二进制转储和原始身份体，移除已识别的密钥/PSK 前缀。原有主日志未改成公开安全的日志，对外分享前仍需脱敏。图片 IO、编码和磁盘日志仍在既有后台线程执行，没有给音视频回调增加磁盘操作。

## 建议车测步骤

1. 安装本诊断 APK 后重新启动应用，确认导出中有 `schema=20261108-v1`。
2. 尽量冷启动连接，记录手机和车机上的操作及卡住时刻；连接后先导出一份。
3. 播放确认具有封面的音乐，保持 15—30 秒；暂停/恢复，切换两三首歌，再导出。
4. 测试手动断开、再次连接，结束后再导出。注明仪表歌名、专辑名、进度、封面的实际表现。
5. 使用应用原有“导出日志”即可带上独立诊断；无需 root 或单独提取私有文件。长时间测试后仍建议及时导出，进程重启会清理上个进程的独立归档。
